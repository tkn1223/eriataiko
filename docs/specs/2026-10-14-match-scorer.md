# 得点入力の担当（同じ試合を 2 人が同時に入れられないようにする。roadmap「1 の続き」）

作った日: 2026-10-14

## なぜ作るか

いまは同じ試合の得点を 2 人が同時に入れられ、あとから押したほうで**黙って上書き**される。
当日はコート横の人とスコア台の人が両方入れることが普通に起きるので、点が食い違っても誰も気づけない（`docs/roadmap.md` の「1 の続き」）。
できあがると、1 つの試合に入力する人は 1 人だけになり、ほかの人には「愛知南のたろうさんが入力しています」と出て、引き継ぐかを選べる。

作り方の ①〜⑧ は 10/4 に PR #57 でたかひろさんと決定済み。残っていた ⑧ の出し場所と「直す」の扱いを 10/14 に yosuke さんが決めた。
**#74（進行表）が結果LIVE の購読まわりを触っているので、#74 の枝の上に積む**（#74 → この PR の順にマージ）。

## 決めたこと

**10/4 たかひろさんと決定（PR #57 コメント）**
1. 担当は**試合**に付く（コートではない）。最後に点を入れてから **5 分**で自動的に外れる
2. 名前には**チーム名を添える**（「愛知南のたろうさん」。同じニックネームの人がいるため）
3. 担当のいない進行中の試合には**目立つ印**を出し、気づいた人が押せるようにする
4. 引き継がれた人の ＋ − は**断り、理由を出す**（「◯◯さんが引き継ぎました」）。取り戻せる（引き継ぎ直す）
5. 担当を取る操作が電波で失敗しても、**入力は止めない**（点は押せる。担当を取るのは裏で続ける）
6. 「得点を入力する」は **1 試合に 1 回**だけ押す。ボタンは大きく（44px 以上）
7. **試合の終了は担当だけ**が押せる。別の人が終わらせたいときは先に引き継ぐ
8. 担当でない人から遅れて届いた点は**断る**（いまの担当の点を上書きしない）。断られた人には「◯◯さんが担当しています」と**送れなかった点数**を出す

**10/14 yosuke さんが決定**
9. ⑧の出し場所は**そのコートのカードの中**（赤い枠。「閉じる」で消える。ほかのコートは触れる）
10. 終わった試合の「**直す**」は**誰でも押せて、押した人がその試合の担当になる**（言われたその場で直せる。直している間はほかの人とぶつからない）
11. （#57 の宿題）送れていない点があるまま別の人として入り直したときの名前のずれは、ここで直す。送るときの担当の確かめで、入り直した人が担当でなければ ⑧ と同じく断られて知らせる

## 画面のイメージ

担当がいない進行中の試合（選手の画面）:
```
┌ コート3 ──────────────── LIVE ┐
│ 愛知中央・たろう vs 愛知南・はなこ │
│  11  -  10                       │
│ ⚠ 入力する人がいません             │
│ ［   得点を入力する   ］            │
└────────────────────────────┘
```
ほかの人が担当中（自分は担当でない）:
```
│ 愛知北のじろうさんが入力しています  │
│ ［ 引き継ぐ ］                      │  → 確認「愛知北のじろうさんが入れています。引き継ぎますか？」
```
自分が担当:
```
│ 第1ゲーム ［−］11［＋］［−］10［＋］ │
│ ［試合を終了する］ ［入力をやめる］  │
```
観戦者には「得点を入力する」「引き継ぐ」は出ない（担当の名前は見える）。

## やること

**表のつくり（`supabase/migrations/` に 1 つ足す）**
- `matches` に「いまの担当（参加者）」と「担当が最後に点を入れた時刻」の 2 列を足す。`matches` は購読の対象なので、担当の変化もそのまま全員の画面に届く
- 書き込みは今までどおり入口（Route Handler）だけ。読める設定だけ（AGENTS.md の 3）
- **本番に流すのは人の判断**（先に `db:push`、あとからコード）

**入口（`src/app/api/matches/[matchId]/scorer/route.ts` を新しく）**
- `POST` 担当を取る（空いていれば取る。ほかの人が担当中なら、引き継ぐと明示したときだけ取る）
- `DELETE` 担当をやめる（自分が担当のときだけ）
- 担当が 5 分点を入れていなければ、誰が取っても空いているのと同じ扱い
- 決まりの判断は `src/usecases/` に（入口は受け取って渡すだけ）。`write_logs` に残す

**今ある入口に担当の確かめを足す**
- 得点の保存・試合の終了: 担当でなければ断る（日本語の理由と、いまの担当の名前を返す）。担当なら「最後に点を入れた時刻」を更新
- 終了の取り消し（直す）: 誰でも押せて、押した人が担当になる

**画面（結果LIVE）**
- 上のイメージどおり。担当の名前はチーム名つき
- 担当を取るのが失敗しても ＋ − は押せる（⑤）。送った点が担当でないと断られたら、カードの中に「◯◯さんが担当しています ／ 送れなかった点：第1ゲーム 12-10 ／［閉じる］」（⑧⑨）
- 試合を終了するボタンは担当だけ（⑦）
- 1 つ前の［直す］は誰でも。押した人が担当（⑩）

## やらないこと

- 運営だけが使える特別な権限（運営と選手を見分ける仕組みが無い）
- 担当の時間（5 分）を画面で変える設定
- 進行表への入力（結果LIVE だけ。#74 で決定）
- 1-2 つ以上前の試合を直すこと

## 受け入れ基準

- [ ] 担当がいない進行中の試合に「入力する人がいません」と「得点を入力する」が出る。押すと自分が担当になり、＋ − と「試合を終了する」が出る
- [ ] ほかの人の画面には、その試合に「愛知南のたろうさんが入力しています」（チーム名つき）と「引き継ぐ」が出る。担当の変化はその場で映る
- [ ] 「引き継ぐ」→ 確認 → 引き継ぐと担当が移る。前の担当の人の ＋ は断られ、理由が出る。前の人も引き継ぎ直せる
- [ ] 担当が最後に点を入れてから 5 分たつと、ほかの人が確認なしで担当を取れる
- [ ] 担当でない人から点が届いても保存されず、いまの担当の点が残る。断られた人のカードに「◯◯さんが担当しています」と送れなかった点数が出て、「閉じる」で消える
- [ ] 担当を取る操作が失敗しても ＋ − は押せ、点は送られる（あとで担当が取れれば保存される）
- [ ] 「試合を終了する」は担当だけに出る。入口でも担当でなければ断る
- [ ] 1 つ前の「直す」は誰でも押せて、押した人がその試合の担当になる
- [ ] 「入力をやめる」で担当が外れる
- [ ] 送れていない点があるまま別の人として入り直すと、その点は入り直した人の名前で保存されず、⑧ と同じく知らせが出る
- [ ] 観戦者には「得点を入力する」「引き継ぐ」が出ない。入口も観戦者は断る（403）
- [ ] 担当を取る・引き継ぐ・やめるが `write_logs` に残る
- [ ] 新しい列が anon から読めて書けない（`tests/rls.test.ts`・`tests/schema.test.ts` にテスト）
- [ ] 375px と 390px で横にはみ出さない（担当の名前・知らせが出た状態も。Playwright で実測）
- [ ] 押せるところは 44px 以上
- [ ] `npm run check && npm test && npm run test:e2e` が緑

## つくりの方針

- 担当かどうか・5 分で外れるか・引き継げるかの判断は**純粋な関数**（`src/domain/` か `src/usecases/`）。時刻は呼び出し側から渡す
- 入口は AGENTS.md の順（requirePlayer → zod → 書き込み → logWrite → toErrorResponse）
- 画面側は #57・#66 の提出箱（`use-score-sync.ts`）と購読（`use-live-updates.ts`）を使い回す。断られた理由の判断は `save-retry-policy.ts` に足す
- コミットは「表のつくり → 入口と決まり → 今ある入口の確かめ → 画面 → 仕上げ（roadmap・e2e）」に分ける
- e2e は 2 つのブラウザで（取る・引き継ぐ・断られる・5 分は時刻をずらして確かめる）
