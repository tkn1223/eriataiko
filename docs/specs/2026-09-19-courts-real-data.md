# 結果LIVE（/courts）を本物のデータから読む（1-a）

作った日: 2026-09-19

## なぜ作るか

結果LIVE は今も見本の固定データ（`src/ui/courts/sample-data.ts`）を出している。当日いちばん見られる画面なのに、実際の試合も点数も出ていない。
`docs/roadmap.md` の最優先「1. 結果LIVE を本物の得点につなぐ」の最初の 1 本（1-a）。
**読むだけ。** 押しても保存しないのは今までどおりで、保存は次の 1-b でやる。

## 決めたこと（yosuke さん確認済み）

1. **コートは常に 8 面出す。** 試合の無いコートは「予定なし」
2. **「◯/◯ 試合消化」は、いまの段だけを数える。** 決勝の試合が 1 つでも始まったら（waiting 以外になったら）数える対象もラベルも「決勝トーナメント」に切り替わる
3. **観戦者には「＋」「−」を今回から出さない。** 「試合を終了する」も出さない。得点は見るだけ

## やること

`src/app/(app)/courts/page.tsx` が、開いたときに 1 回だけ DB を読み、今までと同じ画面部品に渡す。

- **大会**: `is_current` の 1 件（#53 の `findCurrentCompetitionId` を使う）
- **段のラベルと消化数**: 上の決定 2。消化 = その段の `done` の試合数 / その段の全試合数
- **コート 1〜8 ごとに**
  - 進行中: そのコートの `status = 'live'` の試合（2 つあれば `order_in_court` の若いほう）
    - 部のラベル（`divisions.sort_order` 順に 1部/2部/3部。#53 と同じ決め方を使い回す）
    - 回戦（`matchups.round_name`）、両側のペア名（`match_players` → 参加者 → 選手。`order_in_pair` 順）
    - チーム色（`matchups.side_x_team_id` → `teams.team_number`。1〜4 に収める）
    - 枠の数は `matches.max_game_count`、入っている得点は `game_scores`
  - 次: そのコートの `status = 'waiting'` で `order_in_court` がいちばん若い試合
  - 進行中が無く次があれば「呼出待ち」、どちらも無ければ「予定なし」（今の出し分けのまま）
  - 出場者がまだ決まっていない側は、対戦の空枠ラベル（「予選1位」など）を出す
- **「あなたの試合」**: 選手として入っている人が出る試合に印（観戦者は無し）
- **観戦者**: ＋・−・試合を終了する を出さず、各ゲームの得点を数字で見せる
- **つながらない／大会が無い**: myページ（#53）と同じ日本語の案内を出す
- 「入れた点はまだ保存されません」の帯は残す（1-b まで保存しないので）

## やらないこと

- 得点・試合終了の**保存**（1-b / 1-d）。押したときの動きは今までどおり画面の中だけ
- 他の人の得点を**その場で映す**こと（1-c）。自動で読み直さない
- 進行表・対戦表のデータ接続
- 「呼出待ち」から次の試合への自動繰り上げ
- 表のつくりの変更（`supabase/migrations/` は触らない）

## つくりの方針（myページ #53 と同じ形）

- `src/db/courts.ts` … 表を読んで行を返すだけ（`createSupabaseServerClient()`）。読む回数は 5 回前後、すべて `.limit()`
- `src/usecases/build-courts-view.ts` … 行 → 画面の形（純粋な関数。テストが速い）
- `page.tsx` … `getSession()` → 読む → 組み立てる → `CourtsPage` に渡すだけ
- 画面部品の型は `src/ui/courts/types.ts` に移し、`sample-data.ts` は消す（jsdom のテストは自前の小さな値を持つ）
- 画面テスト（e2e）の多くは見本の 8 面の状態（3 ゲーム・同点・長い名前・呼出待ち…）に頼っている。**テスト用の試合を手元の DB に作って終わったら消す**補助（`e2e/helpers/courts-scenario.ts`。#53 の `long-name-player.ts` と同じやり方）で置き換える
- **#53 の枝の上に積む。** `findCurrentCompetitionId`・日本語の接続エラー表示・`enterAsPlayer` を #53 で作ったので、同じものを二重に作らない。PR の宛先は `develop`、本文に「#53 が先」と書く

## 2026-10-04 の書き直し（PR #56 レビュー「一緒に考えてほしいこと」の結論）

たかひろさんのレビューで 2 つの問題が見つかり、yosuke さんが結論を出し、10/4 に了承をもらった。
**上の「決めたこと 1（コートは常に 8 面）」はこの節で置き換える。**

### その 1. 読み込みを 2 つに分ける

1 本の読み込みが「コートに出す（名前・得点が要る）」と「◯/◯ 試合消化（数だけでよい）」を兼ねていて、
**大会が進むほど重くなり**、上限 100 件を超えると**黙ってコートや消化数が欠けた**。

- コートに出すぶんは、`status` が `live` と `waiting` の試合**だけ**を中身つきで読む。終わった試合は読まない
- 「◯/◯ 試合消化」は**件数を数えるだけ**にする（行を持ってこない）
- 残る上限は `src/db/snapshot.ts` と同じく **1 件多く読み、上限を超えたら分かる**ようにする（黙って欠けさせない）

### その 2. 同じ決めごとを 1 か所にまとめる

チームの色・部の色の決めごとが**画面ごとにコピーされ、食い違っていた**（5 チーム目の扱いが 2 通り、扱える部の数が 3 と 6 の 2 通り）。
**結果LIVE だけでなく、入場画面・myページ・進行表・対戦表も含めて、コピーされている全部の場所**を 1 か所にまとめる（たかひろさんの追加のお願い）。

- 色の対応表は `src/domain/class-labels.ts` に集める
- **5 チーム目を 1 チーム目の色に折り返す仕組み（`foldTeamNumber`）は消す**。#58 で 5 チーム目は表が受け付けなくなったため、二度と通らない道になった
- 入場画面の「チームが無ければ薄い色」は残す（チームに入っていない入力係などのため）
- **部の名前は `divisions.name` をそのまま出す。色は並び順（`sort_order`）で決める**（出す文字と色を分ける）
- 部の数は 3 で止めない。色が用意してある 6 部ぶんまで扱う

### コートの枚数は試合から出す

- `[1..8]` の決め打ちをやめ、**試合に入っているコート番号**（進行中・未実施の試合）からカードを出す。番号が飛んでいる日も飛んだまま出す
  - 次の大会は 10 面。決め打ちのままだと 9・10 面の試合が当日ずっと画面に出ない
  - 「何面か」を設定に持たないのは、登録した数と実際の割り当てがずれたとき、どちらが正しいか決められないため
- カードが 0 枚になる場面は文面を分ける
  - 試合が残っているのにコートが 1 つも決まっていない（朝） → 「コートがまだ決まっていません」
  - その段の試合が全部終わった（夕方） → 「全部終わりました」＋結果の見られる場所（対戦表）への案内
  - 大会に試合が 1 つも登録されていない → 「まだ試合が登録されていません」（「全部終わりました」と誤解させないため。レビューで追加）
  - 「全部終わりました」は決勝の試合も最初から登録してある前提。CSV 取り込み（roadmap の 4）で決勝をあとから作る運用にするなら、そのとき見直す

### この節で足す受け入れ基準

- [ ] コートのカードは、進行中・未実施の試合が割り当てられたコートの数だけ出る（8 枚に固定しない。9・10 番のコートも出る。番号が飛んでいても飛んだまま）
- [ ] 試合が残っているのにコートが 1 つも決まっていないとき「コートがまだ決まっていません」と出る
- [ ] 試合が全部終わったとき「全部終わりました」と出て、対戦表への案内がある
- [ ] コート用の読み込みは `live` と `waiting` の試合だけを読む（終わった試合は読まない）
- [ ] 「◯/◯ 試合消化」は件数を数えるだけで出している（試合の行を読まない）。100 件を超える大会でも正しい数が出る
- [ ] 残る一覧の読み込みは上限 + 1 件を読み、上限を超えたら黙って欠けさせずに分かる形にしている
- [ ] チーム色・部の色の対応表が 1 か所にまとまり、入場画面・myページ・結果LIVE・進行表・対戦表のすべてがそこを使っている（`bg-team-1` のような対応のコピーが他に残っていない）
- [ ] `foldTeamNumber` が無くなっている。チームに入っていない人は薄い色で出る
- [ ] 部の文字は `divisions.name` から出る（名前を「初級」に変えると画面も「初級」になる）。色は並び順で決まり、6 部まで色が付く
