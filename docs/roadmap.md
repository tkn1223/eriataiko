## PR の分け方

下の一覧は **1 行 = PR 1 本**になるように割ってある。**そのまま 1 行ずつ出す。**

分け方の目安:

- **「読む」と「書く」を分ける。** 画面に出すのが先、保存はその次
- **「見た目を作る」と「本物のデータにつなぐ」を分ける**
- 画面が複雑なら、**部品ごとに分ける**
- 触るファイルは **10 個くらいまで**を目安に

**ただし、細かく分けても最後まで同じ人が続けてやる。**
途中で人を変えない。変えると「どちらの担当でもない部分」が残る（`AGENTS.md` の「役割分担は無い」）。

**それぞれの行は、それだけで動く形にする。** 「次の PR が来るまで画面が壊れている」を作らない。

| | やること | 終わったと言える状態 |
| --- | --- | --- |
| **1-a** | ~~結果LIVE を**DB から読む**（見本データをやめる）~~ | ✅ 作り終わり（PR #56。レビューの指摘を直し中）。いま進んでいる試合と得点が本物になった |
| **1-b** | ~~`＋` `−` を押したら**保存する**~~ | ✅ 作り終わり（PR #57。#56 の上に積んである）。押した点が残り、開き直しても消えない |
| **1-c** | 他の人の得点を**その場で映す** | 2 台のブラウザで、片方の `＋` がもう片方に映る |
| **1-d** | **試合の終了・取り消し**を入口につなぐ | 「終了」が本当に記録され、取り消しもできる |

**1-a で決めたこと（次の 1-b 以降にも影響する）:**

- コートは常に 8 面出す。試合の無いコートは「予定なし」
- 「◯/◯ 試合消化」は**いまの段だけ**を数える。決勝の試合が 1 つでも始まれば
  （waiting 以外になれば）ラベルも消化数も「決勝トーナメント」に切り替わる
- 観戦者には「＋」「−」「試合を終了する」を出さない。得点は数字で見るだけ
  （`CourtLiveCard` / `CourtsPage` の `canInput` props）
- 部のラベル決め・チーム色の折り返しは `src/domain/class-labels.ts` に共通化した
  （マイページと結果LIVEの両方から使う）
- 詳しくは `docs/specs/2026-09-19-courts-real-data.md`

**1-b で決めたこと（次の 1-c・1-d にも影響する）:**

- 呼出待ちのコートにも次の試合の得点の枠を出す。最初の 1 点で入口の側が自動で LIVE にする
  （「試合開始」ボタンは作らない）
- 送る・送り直す・まとめる仕組みは `src/ui/courts/use-score-sync.ts` に 1 か所だけ持つ
  （画面の部品からは切り離す）。「送り直すか諦めるか」の判断は `src/ui/courts/save-retry-policy.ts`
  の純粋な関数
- つながらない・5xx・429 は間隔を空けて自動で送り直す。それ以外の 4xx は送り直さず、
  入口が返した日本語の理由をそのコートに出す
- 帯の文言は選手にだけ「試合の終了はまだ記録されません（点は保存されます）」に変えた。
  観戦者には帯そのものを出さない（`UnsavedNotice` の `text` props で切り替える）
- 詳しくは `docs/specs/2026-09-19-save-score-from-courts.md`

使う入口（もうできている）:

- `POST /api/matches/[matchId]/scores` … いまの点数をそのまま送る（「＋1」ではない）
- `POST /api/matches/[matchId]/result` … 試合を終了する
- `DELETE /api/matches/[matchId]/result` … 終了を取り消す

**1-c は通信量に注意。** 得点が変わるたびに画面を読み直すと、1 点ごとに見ている全員が
コート 8 面ぶんを取り直すことになる。3,500 回 × 100 人 × 6〜15KB で 1 日 2〜5GB、
Supabase の無料枠（月 5GB）を 1 日で使い切る。**届いた行だけを当てる形**にする。
