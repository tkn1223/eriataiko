# CSV で大会を取り込む（roadmap 4）

作った日: 2026-10-11

## なぜ作るか

大会の中身（大会・部・チーム・選手・組み合わせ）は CSV で入れると 8/29 に決めたが、取り込む仕組みが無い。
いまは手で表に入れるしかなく、`match_settings` の「何ゲームやるか」を試合にコピーする処理も無い。
運営の表（Google スプレッドシート）は印刷用のレイアウトで、毎年形が変わりうるので、**取り込み用の形を別に決め**、
運営の表からは「取り込み用」タブに数式で写してもらう。

## 決まったこと（10/11 たかひろさん）

- たかひろさんが PC でコマンドを実行して取り込む。画面・入口（API）は作らない
- 取り込み用の形を別に決める（運営の表には直接合わせない）
- 人は**選手番号**で書く。番号は年をまたいでずっと同じ人に同じ番号
- 直したら**丸ごと入れ直す**。その大会に点が 1 つでも入っている／始まった試合があれば止める
- 大会・会場・部・チーム・段・ゲーム数も CSV で作る（空の状態から大会ができあがる）
- 「いまの大会」への切り替えは**別のコマンド**

## 取り込み用の形（3 枚。1 つのフォルダに入れる）

**大会.csv**（種類ごとの行）
```
種類,名前,値
大会,第5回 愛知エリア対抗バド大会,2026-11-23
会場,◯◯体育館,9          ← 値 = その会場で使える面数
面数,,9                   ← 今年押さえた面数（コート番号の上限の検査に使う）
チーム,東日本,1            ← 値 = チーム番号（色。1〜4）
部,1部,                   ← 書いた順が並び順
段,予選リーグ,リーグ        ← 値 = リーグ / トーナメント。書いた順が並び順
ゲーム数,予選リーグ/1部,1   ← 段/部 ごとの最大ゲーム数（match_settings）
```

**選手.csv**: `選手番号,名前,チーム,部`（チーム・部は空でもよい＝試合に出ない係の人）

**試合.csv**（1 行 = 1 試合）:
`段,対戦,対戦の順番,チームA,チームB,部,対戦の中の順番,コート,コートの中の順番,A1,A2,B1,B2`
- 同じ「段＋対戦」の行が 1 つの対戦（matchup）になる
- チーム A/B: 大会.csv のチーム名。トーナメントの段ではチーム名でなければ空枠の名前（「予選1位」）として入れ、最後に一覧で知らせる。リーグの段で知らないチーム名は止める
- A1〜B2: 選手番号。トーナメントで未定なら空でよい
- コートは数字（運営の A〜I は取り込み用タブで 1〜9 に写す）
- ゲーム数は書かない。大会.csv の「ゲーム数」から試合にコピーする（8/29 の決定どおり）

## やること

1. `scripts/lib/competition-csv.mjs`（DB を触らない純粋な処理。JSDoc で型）
   - CSV の読み取り（引用符・改行・先頭の BOM に対応。ライブラリは足さない）
   - 3 枚の検査と、書き込む行の組み立て。**問題は全部集めて、行番号つきの日本語で返す**（1 件目で止めない）
2. `scripts/lib/import-competition-db.mjs`（書き込み。service_role の鍵を使う）
   - 同じ「大会名＋日付」の大会があれば: 点（game_scores）が 1 行でもある、または waiting 以外の試合があれば止める。
     無ければ大会の行は残して（is_current を保つため）、部・チーム・参加・段（その下の対戦・試合・出場者・ゲーム数設定）を消してから入れ直す
   - 会場は名前で探して無ければ作る。選手は番号で探して、無ければ作る・名前が変わっていれば直す
   - 書き込みの前に全部検査し終える。途中で失敗したら「もう一度実行してください（丸ごと入れ直すので安全）」と出す
3. `scripts/import-competition.mjs <フォルダ>`（入口）: つなぐ先の URL と件数の要約を出し、`y` を打たれるまで書き込まない（`--yes` で省略）
4. `scripts/set-current-competition.mjs <日付>`: その日付の大会に「いまの大会」の印を移す（外す → 付ける）
5. 見本: `docs/import-sample/` に 3 枚（名前は架空）。seed と同じ形（4 チーム・3 部・予選 6 対戦・決勝 4 対戦）
6. 説明: `docs/import.md`（使い方・各列の意味・運営の表に「取り込み用」タブを作るときのコツ・よく出るエラー）
7. `README.md` と `docs/roadmap.md`（4 を ✅、決めていないことに「アプリのコート表示は 1〜9、会場は A〜I」）を更新

## やらないこと

- 取り込み画面・入口（API）
- 変わったところだけ直す取り込み／点が入ったあとの入れ直し
- 運営の表（印刷用レイアウト）を直接読むこと
- 得点・試合の進み具合の取り込み
- 決勝の空枠を予選の結果から自動で埋めること
- 古い大会を消すコマンド
- コートを A〜I で表示する画面の変更（決めていないことに書くだけ）
- 表のつくりの変更（マイグレーションは足さない）

## 受け入れ基準

- [ ] 見本の 3 枚を空の大会に取り込むと、4 チーム・3 部・予選 6 対戦・決勝 4 対戦・出場者が入り、結果LIVE・対戦表・myページに出る
- [ ] 試合の `max_game_count` が、大会.csv の 段/部 のゲーム数になっている
- [ ] 同じ 3 枚をもう一度取り込むと、件数が増えずに入れ直される。その大会の「いまの大会」の印は残る
- [ ] その大会に点が 1 つでも入っていると、何も書き換えずに止まり、理由が日本語で出る
- [ ] 問題のある CSV（知らないチーム・存在しない選手番号・面数を超えるコート・同じ対戦の中でチームが食い違う・リーグで同じ 2 チームの対戦が 2 つ・トーナメントの対戦が 4 つでない／並び順の重なり 等）は、**何も書き込まず**、全部の問題を行番号つきで出す
- [ ] 選手番号が既にある人は作り直さず、名前が違えば直す
- [ ] トーナメントでチーム名でない値は空枠として入り、取り込み後に一覧で知らされる
- [ ] `y` を打つまで書き込まない。つなぐ先の URL を最初に出す
- [ ] `set-current-competition` で印が移り、印は常に 1 つだけ
- [ ] `npm run check && npm test && npm run test:e2e` が緑

## レビューのあとで決めたこと（10/11 たかひろさん）

- **同じ大会かどうかは日付だけで見分ける。** 同じ日に大会は 1 つだけとみなす。大会名を直して入れ直すと、名前も直る。
  「大会名＋日付」で見分けていたので、名前の誤字を直すと大会が 2 つになり、日付で探す切り替えコマンドも止まって行き止まりになっていた
- **点が入ったあとの選手名の誤字は、当日は直さない。** 直すコマンドは作らない。どうしてもなら Supabase の管理画面で 1 人だけ直す（`docs/import.md` に手順）
- **「今年の面数」が会場の面数より多ければ止める**（書き間違いとして知らせて取り込まない）
