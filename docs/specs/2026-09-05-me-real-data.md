# myページ（/me）を本物のデータにつなぐ

作った日: 2026-09-05

## なぜ作るか

myページは見た目だけ先に作り（`docs/specs/2026-08-16-me-page.md`）、中身は見本の固定データのまま。
表と入場の仕組みができたので、**入場した本人の試合と成績を本物から出す**。

## やること

**選手として入場している人**

- 見出し部: 本人の名前・チーム名（チーム色の丸アバター）・部
- 成績カード: **終了した試合だけ**から計算した「◯勝◯敗」「ゲーム ◯-◯」「得失点 ±◯」
  - 試合の勝敗は `src/domain/match-rules.ts` の `matchOutcome`（上限は `matches.max_game_count`）
  - ゲームの勝敗は `winnerOfGame`。0 対 0 のゲームは数えない
- 今大会の試合: 自分が出る試合だけ
  - 印: 終了は勝ち `○` / 負け `●`、進行中 `LIVE`、未実施 `待`
  - ペアの相手（いなければ「シングルス」）・対戦相手・部（試合の `division`）・回戦（`matchups.round_name`）
  - 終了はゲーム数と各ゲームの得点。未実施は「コート◯・◯試合目」、コート未定なら「コート未定」
  - 進行中の試合はゲーム数を出さない（ゲームが終わった印が表に無いため）。各ゲームの得点だけ出す
  - 並び順: 進行中 → 未実施（コート・順番の若い順）→ 終了
- 「別の人として入り直す」リンク → `/enter`

**観戦者**

- グレーの丸アバター「観」＋「観戦モード」＋「名前を登録すると『自分の試合』が見られます」
- 「選手として入り直す」ボタン → `/enter`。成績や試合一覧は出さない

**データの読み方**

- `page.tsx` は `getSession()` で誰かを見て、`createSupabaseServerClient()` で読む。`getSupabaseAdminClient()` は使わない
- 一覧を読むクエリには全部 `.limit()`
- 読むのは開いたとき 1 回だけ。**自動で読み直さない**（1 点ごとに全員が読み直すと Supabase の無料枠を使い切る）
- 大会が無い・つながらないときは日本語でエラーを出す（`ErrorBlock`）

## やらないこと

- 得点や名前の書き込み（読むだけ）
- 進行中の得点の自動更新（結果LIVE の作りが決まってから同じ方法で）
- 進行表・対戦表のデータ接続（次の順番）
- ヘッダーの大会名を本物にすること
- 入場画面そのものの変更

## 決めたこと

- **観戦者には「観戦モード」を出す。** 何をすれば自分の試合が見られるかを伝える（参考アプリと同じ）。
- **「名前を変更」は入場画面へ送る。** 名前を選ぶ仕組みは入場に既にあるので二重に作らない。
- **成績は終了した試合だけで計算する。** 進行中の点を混ぜると開くたびに数字が動いて信用されない。
- **層を分ける**（`db` が読む → `usecases` が画面の形に組む → `page.tsx` は呼ぶだけ）。結果LIVE と同じ形。
- **部のラベルは `divisions.sort_order` の順に 1部/2部/3部 を当てる。** 名前が違う大会でも色分けが崩れない。
- **チーム無しは灰色のアバター。** チーム色 1〜4 に無理に当てはめない。
- **見本データは消す。** テストは自前の小さな値を持つ。

## 残した宿題

- 進行中の得点の自動反映（結果LIVE と同じ方法で）
- `game_scores` にゲーム確定の印を持たせるかどうか（結果LIVE の保存と合わせて決める）
- 進行表・対戦表のデータ接続
- ヘッダーの大会名を `competitions` から出す
- 進行中の行は開いた時点の得点で止まる（自動更新しないため）。「開いた時点の得点です」の一言を添えるかは、自動更新の方法と一緒に決める
- 大会が無いときのエラー画面の見出しが「Supabase に繋がりません」と `.env` の案内になる（`ErrorBlock` 共通の文言）。本文は正しいが見出しが原因とずれるので、入場画面と合わせて文言を分ける
