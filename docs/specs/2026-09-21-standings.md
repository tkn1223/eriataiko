# 勝敗と順位の計算（3-a。画面は触らない）

作った日: 2026-09-21

## なぜ作るか

対戦表・星取表・順位表（`/bracket`）は今も見本の固定データ。本物につなぐには、先に
**「どちらのチームがその対戦に勝ったか」「順位をどう並べるか」の計算**が要る（`docs/roadmap.md` の 3-a）。
計算ができていないと画面が作れないので、`src/domain/` に純粋な計算だけを作る。**画面も DB も触らない。**
返事待ちの #56・#57 とファイルが重ならないので、待ちの間に進められる。

## 決めたこと（yosuke さん確認済み）

1. **順位表の「◯勝◯敗」はチーム対戦ごと**に数える（1 対戦 = 1 勝敗。中の 3 試合で多く勝ったほうがその対戦の勝ち）
2. **対戦の勝ちは、中の試合が全部終わってから**決まる。途中（2-0 で残り 1 試合）はまだ数えない
3. **対戦の中の勝ち数が同数なら引き分け**（どちらも 1 勝にも 1 敗にもしない）
4. **進行中の試合は順位の計算に入れない**（終了した試合だけ）
5. **並び順は 勝ち数 → ゲーム → 得失点。全部同じなら同順位**（2 位が 2 つなら次は 4 位）
   - 1 つ目は「勝ち数 − 負け数」ではなく**勝ち数**。負け数も引くと、途中経過で 2 勝 2 敗と
     まだ 1 試合もしていない 0 勝 0 敗が同じ順位に見えるため（予選は全チーム同じ数だけ対戦するので、
     終わったときの並びは変わらない）

## やること

`src/domain/standings.ts`（新規）に、次の純粋な関数を作る。

- **対戦（チーム対チーム）の結果**: 中の試合の一覧から `{ finished, winner: 'A'|'B'|null, wonMatches: [a, b] }`
  - 試合の勝敗は既存の `matchOutcome` + `leadingSide`（`src/domain/match-rules.ts`）を使う。作り直さない
  - 0 対 0 のゲームを除くのは既存の `playedGameScores`（`src/domain/scoring.ts`）に任せる
  - 全試合が終わっていなければ `finished: false`（勝ちは未確定）
- **順位表**: 対戦の一覧とチームの一覧から、チームごとに
  `{ teamId, wins, losses, draws, gamesWon, gamesLost, pointDiff, rank }` を返す
  - 数えるのは**終わった対戦だけ**。ゲーム数・得失点は**終了した試合**の全ゲームから
  - 得失点は「自チームの取った点 − 相手の取った点」の通算（`player-record.ts` と同じ考え方）
  - 並びは 勝ち数 → ゲーム（勝ち − 負け）→ 得失点。全部同じなら**同じ順位**を付け、次の順位は人数ぶん飛ばす
- テストは受け入れ基準をそのまま名前にして先に書く（赤を見てから実装）

## 受け入れ基準

- [ ] 対戦の中の試合が全部終わっていれば、勝ち試合数の多いチームがその対戦の勝ちになる
- [ ] 中の試合が 1 つでも終わっていなければ、その対戦の勝ちは決まっていない扱いになる
- [ ] 中の勝ち数が同数のとき、引き分け（どちらも勝ちでも負けでもない）になる
- [ ] 0 対 0 のゲームは数えない（既存の `playedGameScores` を通す）
- [ ] 上限 3 ゲームの試合を 1-0 で終了したとき、その試合はゲームを多く取った側の勝ちになる
- [ ] 順位表の勝敗は、終わった対戦だけで数えられる（進行中・未実施は入らない）
- [ ] 順位表のゲーム数・得失点は、終了した試合の全ゲームから計算される
- [ ] 並びが 勝ち数 → ゲーム → 得失点 の順になる（3 つのテストで 1 つずつ確かめる）
- [ ] 2 勝 2 敗のチームが、まだ 1 試合もしていない 0 勝 0 敗のチームより上に来る
- [ ] 3 つとも同じチームは同順位になり、その次のチームの順位が人数ぶん飛ぶ（例: 2,2,4）
- [ ] 試合が 1 つも終わっていない大会でも、全員 0 勝 0 敗・同順位で返る（エラーにならない）
- [ ] `src/domain/standings.ts` が `@/db` も `@/ui` も import していない
- [ ] `npm run check && npm test` が緑

## つくりの方針

- **既にあるものを使い回す**: `matchOutcome` / `leadingSide` / `gamesToWin`（`match-rules.ts`）、
  `playedGameScores`（`scoring.ts`）。同じ判断を作り直さない（`AGENTS.md`「同じ処理を 3 か所コピーしたら」）
- 入力の型は**表の名前に合わせる**（`teamId` / `maxGameCount` / `gameScores`）。3-b で DB の行から組み立てやすくする
- チームの識別は `teamId`（uuid）で行い、`teamNumber`（色）は画面側の仕事にする
- 「引き分け」は数を `draws` として持つ。順位の比較には使わない（勝ち数で並べる）
- 画面テスト（e2e）は増やさない。この段は計算だけなので Vitest で足りる
