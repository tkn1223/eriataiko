## PR の分け方

**1 画面 = PR 1 本。** 下の番号 1 つが PR 1 本。
番号の中の「やること」は PR の中で進める順番で、PR を分ける単位ではない。

以前は「読む」と「書く」を別の PR に分けていたが、PR の数が増えすぎたので
2026-10-07 に 1 画面ぶんを 1 本で出すことにした。

- **2 画面以上をまとめて 1 本にしない。** レビューで戻ったときのやり直しが大きくなる
- **コミットは「やること」ごとに分ける。** PR は大きくても、レビューする人がコミットを順に追えるようにする
- 画面に関係ない作業（CSV 取り込みなど）は、それだけで 1 本

**細かく分けなくても、最後まで同じ人が続けてやる。**
途中で人を変えない。変えると「どちらの担当でもない部分」が残る（`AGENTS.md` の「役割分担は無い」）。

**PR はそれだけで動く形にする。** 「次の PR が来るまで画面が壊れている」を作らない。

### 1. 結果LIVE を本物の得点につなぐ ★最優先

担当: yosuke さん

**これが無いと、当日の得点がどこにも残らない。** ほかの何より先。

細かく分けていたころに出した 2 本（DB から読む #56、保存する #57）は、そのまま進める。
**残りの 2 つは 1 本の PR にまとめる。** #57 がマージされてから始める。

| やること | 終わったと言える状態 |
| --- | --- |
| ~~結果LIVE を **DB から読む**（見本データをやめる）~~ | **終わった**（#56） |
| `＋` `−` を押したら**保存する** | #57 でレビュー待ち。押した点が残り、開き直しても消えない |
| 他の人の得点を**その場で映す** | 2 台のブラウザで、片方の `＋` がもう片方に映る |
| **試合の終了・取り消し**を入口につなぐ | 「終了」が本当に記録され、取り消しもできる |

使う入口（もうできている）:

- `POST /api/matches/[matchId]/scores` … いまの点数をそのまま送る（「＋1」ではない）
- `POST /api/matches/[matchId]/result` … 試合を終了する
- `DELETE /api/matches/[matchId]/result` … 終了を取り消す

**「その場で映す」は通信量に注意。** 得点が変わるたびに画面を読み直すと、1 点ごとに見ている全員が
コート 8 面ぶんを取り直すことになる。3,500 回 × 100 人 × 6〜15KB で 1 日 2〜5GB、
Supabase の無料枠（月 5GB）を 1 日で使い切る。**届いた行だけを当てる形**にする。
