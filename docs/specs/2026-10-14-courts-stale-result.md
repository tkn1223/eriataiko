# 結果LIVE: 遅れて届いた古い知らせで、確認画面が閉じる・別の試合に差し替わるのを直す

作った日: 2026-10-14

## なぜ直すか

進行表（#74）の自動テストで、結果LIVE の「棄権で終了したあと、直して選び直す」テストが **10 回に 2 回落ちる**ことが分かった（develop でも同じ）。
調べると、**テストだけでなく当日も起きる不具合**だった。

1. 得点係が試合を終了する（例: 棄権を選んで OK）
2. すぐ「直す」を押す → 試合が「直し中」に戻る
3. 「もう一度終了する」で確認画面を開き、棄権を選ぼうとしている
4. そこへ **1 の「終了した」という知らせが遅れて届く** → 画面が一瞬「終わった試合（1 つ前・棄権の印）」に戻り、
   「直し中」の枠ごと作り直されるので、**開いていた確認画面が勝手に閉じ、選んでいた棄権も消える**

間違った記録は残らないが、得点係が戸惑う。手元では知らせが 0.3 秒ほどで届くので起きにくいが、**体育館の弱い電波で知らせが数秒遅れると起きる**。

原因（コード）:
- 点数には「自分が送った値が戻ってくるまでは、それより古い知らせを当てない」仕組みがある（`use-score-sync.ts` の戻り待ち。`docs/specs/2026-10-09-courts-live-and-finish.md`）。**試合の状態（終了・取り消し）には無い**
- 確認画面の開閉と選んだ棄権は、枠（`FixingPanel` など）の中だけで覚えていて、枠が作り直されると消える

あわせて見つかった、まだ確かめていない心配:
- 今の試合の「試合を終了する」の確認画面は**コートに結びついていて、試合に結びついていない**。開いている間にほかの人がその試合を終了すると、**確認画面の中身が次の試合に差し替わったまま開いている**かもしれない。そのまま OK を押すと**次の試合を終了してしまう**（次の試合が 0 対 0 なら入口で止まる）

## やること

1. **試合の状態にも「戻り待ち」を付ける。** 自分が終了・取り消しを送って受け付けられたら、その試合について「最後に自分が送った状態」（done＋終わり方、または live）を覚える。同じ状態の知らせが届くまで、違う状態の知らせは当てない。点と同じく、一定時間（点と同じ 10 秒）たったとき・つながり直したときは待つのをやめる
2. **確認画面を試合に結びつける。** 確認画面の開閉と選んだ棄権を、試合ごとにページ側で覚える。枠が作り直されても閉じない・選択が消えない。**開いている試合が終わった・別の試合に入れ替わったら、確認画面を閉じる**（次の試合の中身に差し替えたまま開いておかない）
3. 心配（コートに結びついた確認画面）が本当に起きるかを、まずテストで確かめる。起きるなら 2 で直す

## やらないこと

- 得点入力の担当（別の PR）
- 進行表（#74）
- 点数の戻り待ちの作りを変えること（今のまま使う）

## 作りの結果

作った日: 2026-10-14

- **試合の状態の戻り待ち**（`use-score-sync.ts`）。終了も取り消しも、送る前に「done か live か」を順に覚え
  （`expectMatchEcho`）、返事で受け付けられたら 10 秒のタイマーを始め、断られたら取り除く。購読の知らせは
  `noteRemoteMatch` が見て、自分が送った状態と一致したらそこまでを消す。**自分の最後の状態が戻るまでは
  false（当てない）**を返す。当てない知らせは、読み直しの「当て直し」にも入れない
  （`courts-page.tsx` の `handleLiveChange`）。つながり直したときは `forgetAwaitingEchoes` が、受け付け済みの
  待ちを捨てる（送っている最中のものは残す）。「一致したらそこまでを消す」判断は、点の戻り待ちと
  同じ関数（`dropThroughEcho`）を使っている
  （**10/14 入力の担当で変更**: 試合の状態は、まだ戻っていない自分の状態の先頭とだけ比べる。担当を取ったときの
  live の知らせを取り消しの戻りと取り違えていたため。`docs/specs/2026-10-14-match-scorer.md` の作りの結果）
- **確認画面を試合に結びつける**（`use-finish-sheets.ts`）。開き閉じと選んだ棄権を、試合の id をキーに
  ページ側で覚える。`CourtLiveCard` と直し中の枠は、これを受け取って出すだけ。開いている試合が終わった
  （または一覧から消えた）一覧が渡されたら、その場で消す。消すのは覚えている値そのもの
  （戻ってきても開いたままに戻らない）
- **心配（コートに結びついた確認画面）は本当に起きていた**。今の試合の確認画面を開いたまま、ほかの人が
  その試合を終了すると、確認画面が次の試合の中身（ペア名・OK）に差し替わったまま開いていた。
  e2e と画面の部品の試験の両方で、直す前に落ちることを確かめてから直した

仕様に書いていなくて決めたこと:

- **戻りの見分けは done か live かだけで、棄権の印（終わり方）は見ない。** 仕様は「done＋終わり方」だったが、
  見ると、ほかの人が先に棄権なしで終了していたとき、その知らせ（終わり方が違う）を「古い知らせ」と
  誤って捨ててしまい、自分の画面に違う勝ちが出たままになる（既存の試験
  「他の人が先に棄権なしで終了していたら、こちらで選んだ棄権で上書きしない」が落ちて分かった）。
  古い知らせを見分けるのには、終了と取り消しの区別（done か live か）で足りる
- **送った状態を覚えるのは、返事を待つ前（送る直前）。** 仕様は「受け付けられたら覚える」だったが、
  点と同じにした。返事より先に知らせが届いたとき、その知らせで待ちを終えられる
  （返事のあとに覚えると、戻ってこない知らせを 10 秒待つ）。10 秒の数え始めは受け付けられたとき。
  断られたら取り除く
- 心配の直し方は「覚える場所をページに移す」。終了の OK は、開いた試合の id で送る
- **戻らないまま待ちが終わったら、1 回読み直す**（レビューで足した）。当てなかった知らせは、自分の
  状態が戻ってきて初めて「それより古い」と言い切れる。戻らないまま待ちが終わる（知らせの取りこぼし・
  送れなかった・入口が何も書かずに成功を返した）と、当てなかった中にほかの人の終了・取り消しが
  混じっていたかもしれず、そのままだと画面の更新まで記録と食い違う。読み直すのは「戻らずに終わった」
  かつ「当てなかった知らせがあった」ときだけ（`subscribeMatchEchoGaveUp`）なので、ふだんは増えない。
  つながり直したときは、もともと読み直すので頼まない

- **途中の状態の戻りを当てずに捨てたときも、「当てなかった知らせ」に数える**（#76 のあとで足した）。
  終了 → 直す と送っている間に届いた「終了」の知らせは、自分の終了の戻りとして当てない。ほかの人がほぼ同時に
  終了していた知らせだった（終わり方が違う）こともあるので、直すが断られて待ちが終わったら読み直す
