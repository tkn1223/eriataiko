## なぜ作るか

- 進行表は全コートが閉じた状態で開く。試合中の試合を見るのに、コートを 1 つずつ押して開く（9 面なら最大 9 回）。
  行を押しても何も起きない。観戦の保護者が「うちの子の試合」を探す手段も無い
- 点を押し間違えたまま次の試合が始まると、その試合はもう直せない（直せるのは試合速報の「1つ前」だけ）。
  星取表・順位が間違ったまま残る
- 上の帯は黒と金で凝っているのに、その下は白い箱と灰色の文字だけで味気ない

## やること

| 画面 | URL | 中身 |
| --- | --- | --- |
| 1a 全コート | `/matches` | 帯の小見出し「進行表 ・ 予選リーグ n/m 試合」、探す欄、コート札の列（押すとそのコートのカードへ移る）、全コートのカード（開閉なし。進み具合の線・▲あなた・いまの試合 2 段＋点・次の試合）。カードを押すと 1b |
| 1c 探す | `/matches`（入力中） | 選手名・チーム名の部分一致。試合中 → これから → 終わった試合の順。候補を選ぶ段は挟まない |
| 1b コートの全試合 | `/matches?court=N` | 札の列（先頭に「‹ 全コート」、開いているコートは黒）、「終わった試合」「試合中」「これから」の見出しで分けて全部出す（隠さない）。1 試合はチームごとに 2 段＋ゲームごとの点 |
| 1d 試合の詳しい画面（試合中・これから） | `/matches/[matchId]` | 試合速報と同じ得点板、［コートNの試合速報を開く］（`/courts#court-N`）、そのコートの前後の試合 |
| 1e 試合の詳しい画面（終了） | `/matches/[matchId]` | ゲームごとの点の表、勝・棄権の札、「入力担当：名前（チーム）」、［得点を訂正する］（選手にだけ）、［星取表で見る ›］ |
| 2b 直す画面 | `/matches/[matchId]/correct` | ゲームのタブ（＋次のゲーム）、得点板と同じ大きさの［−］［＋］、点の数字を押すと数字で直接入れられる、変えた点の下に「元は 8」、棄権の 3 択、下に「変えるところ」のまとめ、［この内容で訂正する］ |
| 2c 完了 | `/matches/[matchId]?corrected=<直したゲーム番号>` | 1e に戻り、上に緑の帯「✓ 訂正しました」、直した点を金の地で数秒 |

書き込みの入口: **`PUT /api/matches/[matchId]/correction`**（新規）

- 本文: 全ゲームの点（`{ gameNumber, sideAScore, sideBScore }[]`）と、棄権した側（`'A' | 'B' | null`）
- 順番は AGENTS.md のとおり: `requirePlayer()` → zod → `src/usecases/correct-match.ts` → `logWrite(player, 'match.correct', …)` → `toErrorResponse`
- 断るとき（どれも日本語。何も書かない）
  - 試合が無い: 404
  - 終了していない: 409「この試合はまだ終わっていません。試合中の点は試合速報で直してください。」
  - ゲーム番号が 1 未満・上限（`max_game_count`）を超える・重複: 400
  - 1 点も無い: 400（`hasAnyPoint`）
  - 同点: 400（`canFinishMatch` を使い回す。終了と同じ判定）
- 書き方
  - 試合の状態・終了時刻・入力担当は**触らない**（終わったまま）
  - 棄権の印（`ending`）は、**終了したままのときだけ**書く（読んだあとに試合速報で「訂正」されて試合中に戻っていたら書かずに 409）
  - 点は送られた全ゲームを**まとめて上書き**する。ゲームを消すときは 0 対 0 で送る（0 対 0 のゲームは数えない決まり）
  - 同じ内容を送り直せば必ず同じ結果になる。途中で切れても、もう一度押せば直る
- 表のつくりは変えない（新しい表・列なし。本番の `db:push` は要らない）

## やらないこと

- 試合速報の「1つ前［訂正］」は**今のまま残す**（試合中に戻すやり方）。進行表からの訂正だけが「終わったまま書き換え」
- 試合速報のコート札（デザイン 3a）、myページの試合中（3b）、対戦表（3c）、下のメニュー（3d）は別の PR
- 決勝の組み合わせへの影響の知らせ（2f）。予選の順位から決勝の空枠を埋める仕組みがまだ無いので、起きない
- 訂正の履歴（誰がいつ）を画面に出す。記録は `logWrite` に残る
- 運営だけが直せる仕組み
- 「全試合｜自分の試合」の切り替え（**なくす**。自分の試合は myページと▲あなたで見る）

## 受け入れ基準

- [ ] 進行表を開いた直後、何も押さずに全コートのいまの試合（両方の名前・点）と次の試合が見える
- [ ] コート札を押すとそのコートのカードへ移る。カードを押すとそのコートの全試合が出て、終わった試合も隠れていない
- [ ] 選手として入ると、自分の出番（これからの試合）があるコートの進み具合の線に「▲あなた」が出る。観戦者には出ない
- [ ] 探す欄に名前の一部かチーム名を入れると、その試合が試合中 → これから → 終わった試合の順に出る
- [ ] 1a のカードを押すとそのコートの全試合（1b）が開き、1b と 1c の行のどれを押しても、その試合の詳しい画面が開く
- [ ] 試合中の詳しい画面には得点板と［コートNの試合速報を開く］が出て、押すと試合速報のそのコートへ移る
- [ ] 終わった試合の詳しい画面には、ゲームごとの点・勝の札・棄権の札（棄権のとき）・入力担当の名前が出る
- [ ] ［得点を訂正する］は、終わった試合を選手が見たときだけ出る。観戦者・試合中・これからの試合には出ない
- [ ] 直す画面で点を変えると、その点の下に「元は ◯」が出て、下のまとめに「第◯ゲーム ◯-◯ → ◯-◯」が出る
- [ ] ［この内容で訂正する］を押すと詳しい画面に戻り「訂正しました」が出る。星取表・順位表・myページの数字も直した点で出る
- [ ] 2 試合以上前の試合も直せる。直したあとも試合は「終了」のまま、そのコートの今の試合は進行中のまま
- [ ] 棄権を付ける・外すができ、勝ち負けがそれに合わせて変わる

- [ ] 入場していない人が訂正の入口を呼ぶと 401 で断られる
- [ ] 他の人が試合速報で点を入れると、進行表と詳しい画面にその場で映る（今と同じ）

## 決めたこと

1. **誰が直せるか: 入場した選手なら誰でも**（11/22 依頼者。「いたずらする人はいない、性善説で考える」）。
   観戦者には［得点を訂正する］を出さない（入口も `requirePlayer()` で断る）
2. **直したあと: 終わったまま点と棄権だけ書き換える**（11/22 依頼者。デザインの 2e-B）。
   - **2026-08-29 の決定「終了した試合は直接は直せない（取り消してから直す）」をここで覆す。**
     あの決定は「順位発表後に誤って押しても黙って結果が変わらない」ためだった。今回は、直す画面そのものが
     「元は ◯」と「変えるところ」を見せて確かめる形なので、黙っては変わらない。取り消してから直すやり方だと、
     2 試合以上前の試合を直すたびに、同じコートに「試合中」が 2 つできて試合速報が混乱する
   - 取り消しのやり方（試合速報の 1つ前［訂正］）は残す（依頼者決定）
3. **詳しい画面に入力担当の名前を出す**（依頼者決定）。終了しても `matches.scorer_participant_id` は残るので、
   それを名前とチームにして出す。いなければ行ごと出さない
4. 直す画面の［−］［＋］・タブ・棄権の 3 択は、入口に送る前の**手元の値**だけを変える（試合速報と違い 1 点ずつ送らない）。
   ［この内容で訂正する］で全部まとめて送る
5. 進行表は**見るだけの画面ではなくなる**（2026-10-14 の決定 1 を変える）。ただし「点を入れる」のは今も試合速報だけで、
   進行表からは「終わった試合を直す」だけ
