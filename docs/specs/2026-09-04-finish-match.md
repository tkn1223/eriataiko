# 結果LIVE — 試合終了の判定と、終了の確認画面

作った日: 2026-09-04
書き直した日: 2026-09-07（PR #52 レビュー指摘の反映。下の「2026-09-07 の書き直し」を参照）

## なぜ作るか

いまの結果LIVE は「ゲーム終了」を押すといくらでも次のゲームが増える（実際に第 4 ゲームまで
並んだ状態を確認した）。0 対 0 のまま押すこともでき、意味のない記録が残る。

当日、得点を入れるのは片手・汗ばんだ指。**誤タップの歯止めが 1 つも無いのが、いまの一番の穴。**

たかひろさんと相談して次が決まった。

- **21 点での自動終了は入れない。** 部によって 21 / 15 / 11 点と違い、
  「何点先取かは表に持たない」は 8/20・8/29 に 2 回決めた方針。覆さない
- **したがって確認画面が唯一の歯止めになる。** ここを丁寧に作る
- **試合が終わる条件はゲーム数で決まる。** 予選リーグ = 1 ゲーム、決勝トーナメント = 2 ゲーム先取（最大 3）
- 結果LIVE の画面は yosuke 側の担当。`develop` から枝を切ってよい

## 2026-09-07 の書き直し（PR #52 レビュー指摘）

最初にこの画面を作ったとき、`docs/specs/2026-08-29-score-input-backend.md` の決定
（「上限ゲーム数ぶんの枠を最初から並べ、どの枠も押せる」「表に『そのゲームが終わった印』を
持たない」）と逆の形（進行中の 1 ゲームだけ出して「ゲーム終了」で次へ送る形）で作ってしまい、
たかひろさんのレビューで 5 点の指摘が来た。この節はその反映内容。

1. **画面の形を 8/29 の決定に合わせた。** 「ゲーム終了」ボタンを無くし、上限ゲーム数ぶんの
   枠を最初から並べて、どの枠も押せるようにした。ボタンは「試合を終了する」1 つだけ。
   確認画面は残すが、確認するのは「試合の終了」（見出しは常に「この試合を終了します」）
2. `GameScore` 型が `src/domain/match-rules.ts` と `src/domain/scoring.ts` の 2 つに
   分かれていたのを、`scoring.ts` の 1 つ（`{ gameNumber, sideAScore, sideBScore }`）にそろえた
3. 「1 ゲームぶんの `hasAnyPoint`」（画面側）と「試合全体の `hasAnyPoint`」（`scoring.ts`）が
   同じ名前で意味が違っていたので、画面側を消して `scoring.ts` のものだけにした
4. **「同点（勝ちゲーム数が同数）では試合を終了できない」を `src/domain/match-rules.ts` の
   `canFinishMatch` にまとめ、保存の入口（`usecases/finish-match.ts`）と画面の両方が
   同じ関数を呼ぶようにした。**「1 点も入っていない」の判定はここに混ぜず、`scoring.ts` の
   `hasAnyPoint` のまま残した
5. 21 点でボタンの色が変わる作り（`reachedTwentyOne`）を消した。ボタンは常に同じ色

## やること

**上限ゲーム数ぶんの枠を最初から並べ、どの枠も押せるようにする**

```
第1ゲーム  [ 21 ] [ 15 ]  ← 押せる
第2ゲーム  [  0 ] [  0 ]  ← 押せる    枠の数 = matches.max_game_count
第3ゲーム  [  0 ] [  0 ]  ← 押せる

        [ 試合を終了する ]
```

- 枠の数は `matches.max_game_count`（見本データでは `maxGameCount`）ぶん
- **どの枠も押せる。** まだ点の入っていない枠（0 対 0）も、既に点が入っている枠も同じように
  「−」「＋」で動かせる
- 表に「そのゲームが終わった印」を持たない方針（`game_scores` はゲームごとの得点が並ぶだけ）
  なので、「終わったゲーム」「進行中のゲーム」を分けて持たない。0 対 0 のゲームは
  `playedGameScores`（`scoring.ts`）で数えない扱いにし、それだけで見分ける
- **ボタンは「試合を終了する」1 つだけ。** 押すと、その試合の状態に応じて次のどれかになる

**「試合を終了する」を押したときの流れ**

1. 1 点も入っていなければ、確認画面を出さずカードの中に「まだ点が入っていません」と出す
2. 同点（勝ちゲーム数が同数）なら、確認画面を出さずカードの中に「同点では終了できません」と出す
3. どちらでもなければ確認画面（下から出るシート。`src/ui/components/bottom-sheet.tsx`）が出る。
   見出しは常に「この試合を終了します」。中身は実際にプレーされた各ゲームの得点と
   勝ったペア（同点なら「引き分け」。バドミントンでは実際には起きないが型としては許す）、
   それと試合全体の勝ちペアとスコア（「2-0」のような、勝った側が先の表記）
4. ボタンは「OK」と「戻る」。「戻る」は何もせず閉じる
5. 「OK」でそのコートが「終了」の見た目になる（保存はまだしない。下の「やらないこと」を参照）

**押せないとき**（確認画面を出さず、カードの中に案内を出す）

- 1 点も入っていない … 「まだ点が入っていません」（`scoring.ts` の `hasAnyPoint`）
- 同点（勝ちゲーム数が同数） … 「同点では終了できません」（`match-rules.ts` の `canFinishMatch`）

**終了したコートの見た目**

- 右の「LIVE」を「終了」に変える（点滅を止める）
- 枠（−・＋・得点）と「試合を終了する」を消す
- 各ゲームの結果のチップ（0 対 0 の枠は出さない）は残し、「勝ち: 佐々木・井上（2-0）」を足す
- 「次」の試合はそのまま出す

## やらないこと

- 21 点などの点数による自動終了
- 得点や終了の保存（今回も画面の中だけ。「まだ保存されません」の帯はそのまま）
- 本物のデータにつなぐこと（次の段）
- 終了の取り消し
- 終わったコートを次の試合に自動で繰り上げること
- 進行表（`/matches`）側の得点入力

## 決めたこと

- **同点では終了できない。** バドミントンに引き分けは無く、勝者が決まらないと順位の計算が崩れる。
- **終了したら「終了」と出して得点ボタンを消す。** 終わった試合に点を入れられないようにする。
- **判定は `src/domain/` に純粋な計算として置く。** 本物のデータにつなぐ段でそのまま使い回す。
  - `gamesToWin(maxGameCount)` … 上限の半分を切り上げ
  - `winnerOfGame(score)` … `'A' | 'B' | null`（同点は null）。`score` は `scoring.ts` の `GameScore`
  - `matchOutcome(scores, maxGameCount)` … 終了したか・どちらが勝ちか。`scores` は
    上限ゲーム数ぶんの枠をそのまま渡してよい（`playedGameScores` で 0 対 0 の枠を内部で除く）
  - `canFinishMatch(scores, maxGameCount)` … `{ ok: true }` か `{ ok: false, reason: '…' }`。
    見るのは「同点かどうか」だけ（「1 点も入っていない」は `scoring.ts` の `hasAnyPoint` の役割）
  - `leadingSide(wonGames)` … 勝ちゲーム数が多いほうの側（同数は null）。
    **画面に出す勝ちペアはこれで決める。** 終了は人が押したときだけなので、決勝（上限3ゲーム）を
    1-0 のまま終了することがある。そのとき `matchOutcome().winner` はまだ null で、
    勝ちペアが確認画面にもカードにも出なかった
- **`maxGameCount` は `matches.max_game_count` と同じ名前・同じ意味にする。**
  本物のデータが来たら差し替えるだけで済む。
- **表に「そのゲームが終わった印」を持たない。** 枠を最初から並べることで、
  「終わったゲーム」「進行中のゲーム」を分けて持つ必要が無くなる（本物のデータの形とそろう）。
- **「Nゲーム目」の表示を無くした。** どの枠も同時に押せる形になったので、
  「いま何ゲーム目か」という単一の状態が無くなったため。
