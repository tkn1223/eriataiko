# 進行表（/matches）を本物のデータにつなぐ（roadmap 2）

作った日: 2026-10-14

## なぜ作るか

進行表は、アプリで**最後に残った見本データの画面**（`src/ui/matches/sample-data.ts`）。当日このまま開くと、
「次にどのコートで誰が出るか」を確かめに来た選手を、**実在しない試合や間違ったコートに呼んでしまう**（`docs/roadmap.md` の 2「なぜ作るか」）。
本物にすると、選手が自分の出番を進行表で確かめられる。

roadmap の「決めていないこと」の 1 つ目（得点を入れる場所はどっち？）が 2 の前提だった。
**ミーティング（10/8 → 延期後）でたかひろさんから「とりあえず進めて」と言われたので、yosuke さんが決めた**（10/14）。PR でたかひろさんに確認してもらう。

## 決めたこと（yosuke さん。10/14）

1. **得点を入れる場所は結果LIVE だけ。** 進行表は**見るだけの画面**にする（得点入力のシートを外す）。
   得点の仕組み（保存・その場で映す・終了・直す・棄権・これから作る担当）が 1 か所で済み、2 か所から入って食い違うことが起きない
2. **進行中の行を押しても何も起きない。** 行は押せない見た目にする
3. **点数と試合の進み具合は、結果LIVE と同じ仕組みでその場で映す**（`matches` と `game_scores` の変化を受け取り、届いた分だけ当てる。点のたびに読み直さない）。同じ試合が 2 か所で違う点数に見えないようにする
4. （#56 の決めごとを引き継ぐ）コートは決め打ちせず、**試合に入っているコート番号**から出す。番号が飛んでも飛んだまま。コート表示は数字（1〜9）のまま（A〜I は決めていないので触らない）

## やること

**データを読む（`src/db/matches.ts` とは別に、進行表用の読み取りを足す。結果LIVE の `src/db/courts.ts` と同じ形）**
- いまの大会の**全部の試合**（終わった・進行中・これから）を、コート・試合順・部・回戦・両ペアの名前・各ゲームの点数・終わり方（棄権）つきで読む
  - 進行表は終わった試合も出す画面なので、結果LIVE と違って全部読む。大会の規模（100 人・1 人 5 試合で 125 試合程度）に余裕のある上限を付け、**上限 + 1 で超えたら画面に知らせる**
- 自分の参加者（選手として入った人だけ）
- 開いたときに読み、そのあとは届いた変化だけを当てる。読み直すのは結果LIVE と同じ場面だけ（つながったとき・知らない試合の変化）

**画面**
- コートごとのカード（試合のあるコートだけ、番号順）。見出しに「現在◯試合目」・「残り◯試合」／「すべて終了」。開閉できる
- 試合の行: 試合順・部（`divisions.name`、色は `class-labels.ts`）・両ペアの名前・各ゲームの点数・進行中は LIVE・勝った側は太字（**棄権は点数に関係なく相手の勝ち**＝#71 の決まりの関数を使い回す）・棄権の試合には「棄権」の印
- 終わった試合は最初は隠し、「✓ 終了した◯試合を見る」で出す（今の見た目のまま）
- コートが決まっていない試合は、最後に「コート未定」としてまとめて出す
- 絞り込み「全試合」「自分の試合」は**選手として入った人だけ**に出す。観戦者には「全試合」だけ
- 自分の試合には「あなたの試合」の印（選手だけ）
- 得点入力のシート（`score-sheet.tsx`）と「入れた点はまだ保存されません」の帯（`unsaved-notice.tsx`）は外す。使う場所が無くなれば消す
- 大会が無い／つながらない／試合が 1 つも無いときは、結果LIVE と同じ日本語の案内
- 自動更新が途切れたら、結果LIVE と同じく「自動更新が止まっています」

**その場で映す**
- 結果LIVE の購読（`src/ui/courts/use-live-updates.ts`）と、届いた行を当てる判断（`apply-live-change.ts` など）を**作り直さず共有する**。購読はアプリ全体で 1 本のまま、結果LIVE と進行表のどちらかを開いている間だけつなぐ

**記録**
- `docs/roadmap.md`: 「決めていないこと」の得点を入れる場所を「結果LIVE だけ（10/14 yosuke。たかひろさん確認待ち）」に、2 を作り終わりに。一番下の「本番のデータベースは追いついている（5 つ）」という古い一文を、今の状態（#58 と #71 の表の変更がまだ本番に流れていない）に直す

## やらないこと

- 進行表からの得点入力・試合の終了（結果LIVE だけ）
- 進行中の行を押して結果LIVE に移ること
- 得点入力の担当（次の PR）
- コート表示を A〜I にすること、320px 対応、決勝の空枠を埋めること（どれも決めていない）
- 表のつくりの変更・新しい書き込みの入口

## 受け入れ基準

- [ ] `/matches` に本物の試合（コート・試合順・部・両ペアの名前・点数）が出る。見本の名前は出ない
- [ ] コートのカードは試合のあるコートだけ番号順に出る（9・10 番も、飛び番号もそのまま）。コート未定の試合は最後に「コート未定」でまとまる
- [ ] 見出しの「現在◯試合目」「残り◯試合」「すべて終了」が試合の状態どおりに出る
- [ ] 終わった試合は最初は隠れていて、「✓ 終了した◯試合を見る」で出る
- [ ] 勝った側が太字になる。棄権の試合は点数に関係なく相手が太字になり、「棄権」の印が出る
- [ ] 進行中の行を押しても何も起きない（得点入力が出ない）
- [ ] 「入れた点はまだ保存されません」の帯が出ない
- [ ] 選手として入った人には「全試合」「自分の試合」が出て、「自分の試合」で自分の出る試合だけになる。自分の試合に「あなたの試合」の印
- [ ] 観戦者には「自分の試合」も「あなたの試合」の印も出ない
- [ ] 結果LIVE で ＋ を押すと、別のブラウザで開いている進行表に数秒で同じ点数が出る（開き直さない）
- [ ] 結果LIVE で試合を終了すると、進行表のそのコートの「現在◯試合目」「残り◯試合」が変わる
- [ ] 点が変わるたびに進行表全体を読み直していない（e2e で読み直しの回数を数える）
- [ ] 自動更新が途切れると案内が出て、つながると 1 回だけ読み直す
- [ ] 大会が無い／つながらない／試合が無いときに日本語の案内が出る
- [ ] 375px と 390px で横にはみ出さない。長い名前・3 ゲームの点数でも崩れない（Playwright で実測）
- [ ] 一覧を読むクエリすべてに `.limit()`。上限を超えたら画面に知らせる
- [ ] 部品は `@/db` を import しない（購読の `@/db/client` を除く）。書き込みは無い
- [ ] 色の対応は `class-labels.ts` だけ
- [ ] 結果LIVE・対戦表・マイページの既存テストが壊れない
- [ ] `npm run check && npm test && npm run test:e2e` が緑

## つくりの方針

- 結果LIVE と同じ層: `src/db/<進行表用>.ts`（読むだけ）→ `src/usecases/build-matches-view.ts`（純粋）→ `load-matches-page.ts`（出し分け）→ `page.tsx`（描くだけ）
- 使い回すもの: `findCurrentCompetition`、`class-labels.ts`、`playedGameScores`（scoring.ts）、勝ち負けの判定（match-rules.ts と #71 の棄権の決まり）、購読と当てる判断（`src/ui/courts/` の `use-live-updates.ts` / `apply-live-change.ts` / `refresh-scheduler.ts`）。**同じ判断を作り直さない**。共有するために置き場所を動かす必要があれば、動かして両方から使う
- コミットは「読む → 画面を本物に（見るだけに）→ その場で映す → 仕上げ（roadmap・e2e）」に分ける
- e2e は `e2e/helpers/` にテスト用の試合を作って消す補助（seed に頼らない、`is_current` は触らない）。2 つのブラウザで結果LIVE → 進行表への映りを確かめる
