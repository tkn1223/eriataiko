# 結果LIVE の仕上げ（その場で映す ＋ 試合の終了・取り消し）

作った日: 2026-10-09

## なぜ作るか

結果LIVE は、本物のデータを読む（#56、マージ済み）と、押した点を保存する（#57、レビュー待ち）までできた。
残りは `docs/roadmap.md` の 1 の 2 つで、「1 画面 = PR 1 本」に従い 1 本にまとめる。

- **他の人の点がその場で映らない。** 開き直さないと、別の人が入れた点も、別のコートの進み具合も見えない
- **「試合を終了する」が記録されない。** 画面の中で終わった見た目になるだけで、開き直すと LIVE に戻る（帯で「まだ記録されません」と断っている）
- **終わった試合を直す道が無い。** 当日「さっきの試合の点が間違っていた」は必ず起きる（たかひろさんとの #56 レビューで決定）

**#57 の上に積む**（#57 の「提出箱」を使うため）。#57 に直しが入ったら積み直す。

## 決めたこと（yosuke さん確認済み）

1. **1 つ前の試合はコートに残し、直せるようにする。次の試合が始まっていても直せる。** 直している間も今の試合の得点は入れられる。カードには「直し中」と分かるように出す
2. **自動で映る仕組みが途切れたら「自動更新が止まっています」と出し、つながったら 1 回だけ読み直す**（間に入った点を取り戻す）
3. **送れていない点があるときに「試合を終了する」を押したら、予約して、点を送り終えてから終了を送る。** 押したら「終了を送っています」と出し、得点係は次の試合に移れる
4. （たかひろさんと決定済み）1 つ前の試合は `matches.finished_at` が一番新しい終わった試合。取り消すと空に戻るので自動で外れる
5. （#57 で決定済み）送れていない手元の点は、届いた点より優先して出す

## やること

**その場で映す**
- 結果LIVE を開いている間、`matches` と `game_scores` の変化を受け取る（ブラウザの Supabase クライアントで**読むだけ**。`src/db/client.ts` は購読専用）。届いた行だけを画面に当てる。**画面全体を読み直さない**（通信量。roadmap の注意）
- 試合の状態の変化（始まった・終わった・取り消された）、コートと順番の変化も当てる。手元に無い試合の変化が来たら 1 回だけ読み直す
- 観戦者にも映す
- 途切れたら案内を出し、つながったら 1 回だけ読み直す

**試合の終了**
- 確認画面の「OK」で `POST /api/matches/[matchId]/result` を送る（既存の入口）。送るのは #57 の提出箱を通し、その試合の点が全部届いてから
- 失敗したら送り直す（つながらない・5xx）。断られたら（4xx）日本語の理由を出す
- 帯「試合の終了はまだ記録されません」を外す

**1 つ前の試合と取り消し**
- コートのカードに「1 つ前：部・両ペア・スコア」と「直す」を出す
- 「直す」→ 確認 → `DELETE /api/matches/[matchId]/result` → その試合が「直し中」として得点の枠付きで出る → 直して「もう一度終了する」
- 1 つのコートに進行中の試合が 2 つあるときは、順番が後の試合を「今の試合」、前の試合を「直し中」とする
- 1 つ前の試合は、コートごとに 1 つだけ読む（終わった試合を全部読まない。#56 の「読み込みを分ける」を守る。上限 + 1）

**そのほか**
- 観戦者には「直す」「試合を終了する」を出さない（今までどおり）

## やらないこと

- 得点入力の担当（「◯◯さんが担当しています」）。次の PR。それまで同じ試合を 2 人が入れたら後から届いたほうが残る
- 進行表・対戦表への自動反映（対戦表は今回も開いたときに読むだけ）
- 2 つ以上前の試合を直すこと（運営が別の方法で行う）
- 表のつくりの変更・新しい入口（API）を作ること

## 受け入れ基準

- [ ] 2 台のブラウザで結果LIVE を開き、片方で ＋ を押すと、もう片方に数秒以内に同じ点数が出る（開き直さない）
- [ ] 片方で試合を終了すると、もう片方でもそのコートが次の試合に切り替わる
- [ ] 観戦者の画面にも他の人の点が映る
- [ ] 点が変わるたびに画面全体を読み直していない（届いた行だけを当てている。e2e で読み込みの回数を数える）
- [ ] 自動更新が途切れると案内が出て、つながると 1 回だけ読み直し、間の点が出る
- [ ] 送れていない手元の点は、届いた古い点で上書きされない
- [ ] 「試合を終了する」→「OK」で、データベースの試合が終了になる。開き直しても終了のまま
- [ ] 送れていない点があるときに終了を押すと「終了を送っています」と出て、点が届いたあとで終了が記録される（点が断られて消えない）
- [ ] 終了したコートに「1 つ前」の試合と「直す」が出る
- [ ] 「直す」で試合が直し中に戻り、点を直して「もう一度終了する」で終了になる。データベースにも反映される
- [ ] 次の試合が進行中でも 1 つ前を直せて、その間も今の試合に点を入れられる
- [ ] 帯「試合の終了はまだ記録されません」が出なくなる
- [ ] 観戦者には「直す」「試合を終了する」が出ない
- [ ] 375px と 390px で、1 つ前の試合・直し中・案内が出た状態でも横にはみ出さない（Playwright で実測）
- [ ] 書き込みは Route Handler 経由だけ。ブラウザの Supabase クライアントは購読と読み取りだけ
- [ ] 一覧を読むクエリすべてに `.limit()`。コートごとの「1 つ前」の読み込みも上限 + 1
- [ ] `npm run check && npm test && npm run test:e2e` が緑

## つくりの方針

- 受け取った行を画面の状態に当てる判断（どの試合のどの枠か、手元の未送信と比べてどちらを出すか、知らない試合なら読み直し）は**純粋な関数**にして速くテストする（`src/ui/courts/apply-live-change.ts` のような名前）
- 購読は 1 か所（`src/ui/courts/use-live-updates.ts` のような部品）。アプリ全体で 1 本の接続にし、結果LIVE を離れたら止める
- 終了の予約は #57 の提出箱（`use-score-sync.ts`）に「終了」も載せる形にし、その試合の点が届いてから送る。送り直し・断られたときの判断は `save-retry-policy.ts` を使い回す
- 1 つ前の試合の読み込みは `src/db/courts.ts` に足す（読む回数を増やすなら報告。5 回・2 段を大きく崩さない）
- e2e は 2 つのブラウザ（Playwright の context を 2 つ）で確かめる。テスト用の試合は `courts-scenario.ts` に足す
