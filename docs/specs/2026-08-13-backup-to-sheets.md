# 当日15分おきに Google スプレッドシートへバックアップ

作った日: 2026-08-13

## なぜ作るか

Supabase の無料プランには自動バックアップも巻き戻しもない。
大会当日にデータが消えたり壊れたりすると、そこで大会が止まる。

## やること

- 大会当日（**2027-01-22 金**）の **10:00〜15:00**、15 分おきに全データを
  Google スプレッドシートへ書き出す（21 回）
- 15 分ごとに**新しいタブ**を作る。名前は日本時間の `HH-mm`（例 `10-15`）
- 1 つのタブに対象の表を縦に並べる。表ごとに見出しを付ける
- タブが 60 個を超えたら、古いものから消す（上限 200 に当たって当日止まらないため）
- 書き出す表は `src/config/backup.ts` の一覧で決める。
  あとで試合や得点の表が増えたら**ここに 1 行足すだけ**

## やらないこと

- **シートから DB へ書き戻す機能。** 当日は人が見て打ち直す
- **常時のバックアップ。** 大会当日だけ動かす
- **通知の作り込み。** 失敗すれば GitHub からメールが来る。それで足りる
- 表ごとにタブを分けること（タブが増えすぎて探せなくなる）

## 受け入れ基準

- [ ] `npm test` が通る（新しい純粋関数のテストを含む）
- [ ] 秘密のヘッダーが無いと 401 が返る
- [ ] 秘密のヘッダーが違う値だと 401 が返る
- [ ] 正しいヘッダーで叩くと、スプレッドシートに `HH-mm` のタブが 1 つできる
- [ ] そのタブに `operators` と `write_logs` が、見出し付きで両方入っている
- [ ] タブ名が既にあるとき、`10-15-2` のように別名で作られる
- [ ] タブが 60 個を超えると古いものだけ消える。`HH-mm` の形でないタブは残る
- [ ] 表の行が 5000 を超えたとき、タブに「一部だけです」と書かれる
- [ ] 定期実行の設定が 2027-01-22 の 10:00〜15:00（日本時間）だけになっている
- [ ] 2027-01-22 以外の日に手で動かすと、何もせず緑で終わる
- [ ] `docs/backup.md` を読めば、Google 側の準備を一人で再現できる

## 決めたこと

### 「15 分ごとに新しいタブ」にした理由

当日データが壊れたとき、**人が見て打ち直す**のが復旧手段。
「14:00 のタブを見て打つ」ができる形が一番分かりやすい。

履歴を 1 シートに積む形より探しやすく、最新だけ上書きする形より
「壊れる前に戻す」ができる。

### 「GitHub Actions から自前の API を叩く」形にした理由

普通の Node スクリプトからは**アプリの DB コードを一切再利用できない**。
`src/db/admin.ts` と `src/config/env.server.ts` が `server-only` を import しており、
Node から import すると必ず失敗する（実測で確認した）。

自前の API を叩く形なら `getSupabaseAdminClient()` も環境変数の検証もそのまま使える。
新しい依存も新しい実行方法も増えない。

### この API は書き込み API の順序に従わない

`AGENTS.md` は「書き込みは `requireOperator()` から始める」と決めているが、
この API は **Supabase には書き込まない**（読むだけ）。
なので順序は当てはまらない。代わりに秘密のヘッダーで守る。

データを返さないので、万一叩かれても情報は漏れない。起きるのはタブが増えることだけで、
それは掃除の処理で抑えられる。

### 定期実行を日本時間で書く

GitHub の定期実行は既定では世界標準時だが、**2026 年 3 月からタイムゾーンを
指定できる**。UTC に換算して書くと読んだ人が毎回 9 時間を足し引きすることになるので、
`timezone: 'Asia/Tokyo'` を付けて日本時間でそのまま書く。日本は夏時間がないのでずれない。

定期実行に「年」は書けないため、このままだと 2028-01-22 にも動く。
最初のステップで日本時間の日付を確かめ、違えばすぐ終了する。

### Google の認証に新しいライブラリを足さない

`jose`（セッションで既に使っている）でサービスアカウントの鍵に署名し、
アクセストークンに交換して Sheets の API を `fetch` で叩く。
`googleapis` は大きく、起動が遅くなるので使わない。

### 時刻は引数で受け取る

タブ名に時刻を使うので、テストで固定できるように `build-snapshot.ts` の中で
`new Date()` を呼ばない。

## 残した宿題

- **定期実行のリハーサル。** タイムゾーン指定は新しい機能なので、当日より前に
  日付を近い日に変えて、本当に自動で動くことを一度確認する。
  一発勝負なので、ここを飛ばすと「動くはずだったのに 1 回も動かなかった」が起きる
- 本番と確認用が同じ DB を共有している（`docs/database.md`）。分けるかは未決
- 大会が終わったらこのワークフローを消すか、日付を次回に書き換える
- 試合・得点の表ができたら `src/config/backup.ts` に足す
