# 結果LIVE の ＋ − を押したら保存する（1-b）

作った日: 2026-09-19

## なぜ作るか

1-a（PR #56）で結果LIVE に本物の試合と得点が出るようになった。ただ、＋ − を押しても**画面の中で数字が動くだけ**で、開き直すと消える。
当日の得点が残らないのがいちばん困るので、押した点を保存の入口（`POST /api/matches/[matchId]/scores`、もうできている）に送る。
`docs/roadmap.md` の 1-b。

## 決めたこと（yosuke さん確認済み）

1. **呼出待ちのコートでは、次の試合の最初の 1 点で試合が始まる。** 呼出待ちのコートにも次の試合の得点の枠を出す。1 点入ると入口の側で自動的に LIVE になる（`src/usecases/save-score.ts` がもうそう動く）。「試合開始」ボタンは作らない
2. **保存に失敗したら、数字は残したまま自動で送り直す。** そのコートに「保存できていません・送り直しています」と出し、送れたら消える
3. **帯は文言を変えて残す。** 「試合の終了はまだ記録されません（点は保存されます）」。得点を入れる人にだけ出す。1-d で消す

- **呼出待ちから始まった試合は、0 対 0 に戻しても LIVE の見た目のまま。** 保存の入口の側も LIVE のままなので、開き直した画面と食い違わないようにする（レビューで決定）

## やること

- ＋ − を押すたびに、**そのゲームの今の点数**をそのまま送る（「＋1」ではない。8/29 の決定）
- 連打しても送る数が膨らまないよう、同じ試合・同じゲームは**送信中は 1 本だけ**。返事が来た時点で数字が変わっていれば、最新の点数をもう 1 回送る
- 送れなかったとき
  - つながらない／サーバーの一時的な失敗 → 数字は残し、間隔を空けて自動で送り直す（1 秒 → 2 秒 → 4 秒 … 最大 10 秒）。コートに「保存できていません・送り直しています」
  - 入口に断られたとき（終了済みの試合・入場が切れた・試合が無いなど） → 送り直さず、入口が返した日本語の理由をそのコートに出す
- まだ送れていない点があるまま画面を閉じようとしたら、ブラウザの「このページを離れますか？」を出す
- 呼出待ちのコートに次の試合の枠を出し、最初の 1 点で LIVE の見た目に切り替える（開き直すと入口の側でも LIVE になっている）
- 観戦者には今までどおり ＋ − を出さない（入口も観戦者は 403 で断る）

## やらないこと

- **試合の終了・取り消しの保存**（1-d）。「試合を終了する」は今までどおり画面の中だけ
- 他の人が入れた点をその場で映すこと（1-c）。同じ試合を 2 台で入れたら、あとから送ったほうが残る
- 保存の入口（API）の作り直し。今あるものをそのまま使う
- 進行表（`/matches`）からの保存
- 表のつくりの変更

## つくりの方針

- 送る・送り直す・まとめる仕組みは、画面の部品から切り離して 1 か所に置く（`src/ui/courts/use-score-sync.ts` のような React の小さな部品）。送り先は `fetch('/api/matches/{id}/scores')`。**Supabase の画面側の鍵では書かない**（AGENTS.md の「破ってはいけない 3 つ」の 1）
- 「送り直すか・諦めるか」の判断（状態コード → 送り直す／理由を出す）は純粋な関数にしてテストを速くする
- 失敗の再現は、Vitest では `fetch` の差し替え、e2e では Playwright の通信の差し替え（`page.route`）で行う
- **#56 の枝の上に積む**（#56 の画面の作りを使うため）。PR の宛先は `develop`、本文に「#53 → #56 → この PR の順」と書く

## 2026-10-04 の書き直し（PR #57 レビュー「点が黙って消える道」の結論）

たかひろさんのレビューで、**送れていない点があるまま下のメニューで別の画面に移ると、確認も出ずに点が消える**ことが分かった。
yosuke さんが結論を出し、10/4 に了承をもらった。

### なぜ消えるか

- 「このページを離れますか？」の確認は、**ブラウザを閉じる・更新するとき**にしか出ない。アプリの中のタブ移動では出ない
- 送れていない点は**結果LIVE の画面の中**で待っているので、画面を移ると一緒に捨てられる（得点が画面より短命）

### 決めたこと

1. **送れていない点を預かる場所を、画面の外（アプリ全体）に出す。** 下のメニューで別の画面に移っても、送り直しを続ける。結果LIVE に戻ったら、まだ送れていない点はその数字のまま出る
2. **「離れますか？」の確認は、アプリごと閉じる・更新するときの保険として残す。** 移動を止めるだけにしないのは、電波が戻るまで得点係が myページや進行表を見に行けなくなるため
3. **画面を離れている間に返事が来ても、印を正しく付け替える。** 1-b のレビューで「画面を離れたら返事を無視する」にしたが、預かる場所が生き続けるようになると、保存できたのに「まだ保存できていない」と覚えたままになるため
4. **送れていない点がある間は、「試合を終了する」を押しても「保存できていません」の案内を残す**（たかひろさんの追加のお願い）

### この節で足す受け入れ基準

- [ ] 送れない状態で ＋ を押し、下のメニューで別の画面に移ってから電波が戻ると、その点がデータベースに保存されている
- [ ] 別の画面にいる間に保存できた場合、結果LIVE に戻ったとき「保存できていません」は出ていない
- [ ] 送れていない点がある間に結果LIVE に戻ると、押した数字のまま出て、「保存できていません」が出ている
- [ ] 送れていない点があるままブラウザを閉じる・更新しようとすると、確認が出る（今までどおり）
- [ ] 送れていない点がある試合で「試合を終了する」を押しても、「保存できていません」の案内が消えない。送れたら消える
- [ ] 観戦者には今までどおり ＋ − も帯も出ない

### 作りの結果（2026-10-06）

- 預かる場所は `use-score-sync.ts` のモジュールに 1 つ（`appScoreSyncStore`）。画面（`useScoreSync` を呼ぶ部品）が外れても残る。`(app)` の layout に Provider を置く案は、layout の作りに頼ることになるのでやめた
- 戻ってきた画面の初期値は `initial-live-scores.ts`。サーバーから読んだ得点に、未送信のゲームだけ上書きする
- 「未送信」は、送信中・送り直し待ち・入口に断られたまま、をぜんぶ含む（ブラウザを閉じようとしたときの確認も同じ判定）
- 終了したカードの案内は、「勝ち: ◯◯（2-0）」の行の下に、終了前と同じ見た目（赤の 13px 太字 1 行）で出す
- 「離れますか？」の確認は預かる場所が持つ（点を預かっている間だけ付け、無くなったら外す）
- 預かる場所は「この試合で一度でも点を押したか」も覚える。呼出待ちから始めた試合を 0 対 0 に戻したまま別の画面に移っても、戻ると LIVE の見た目のまま（上の「0 対 0 に戻しても LIVE のまま」と同じ決まり）
- 預かる場所はサーバー側の描画では使わない（サーバーでは全員で 1 つになり、ある人の点が別の人の画面に混ざるため）。サーバーでは何も預からず、描画も常に空を見る


### 残した宿題（10/6 yosuke さん判断）

- **送れていない点があるまま、別の人として入り直したとき。** 点数は消えず正しいままだが、送り直しが次に入った人の名前で届き、`write_logs` に別の人として残ることがある（退場から入り直しまでが送り直しの間隔より短いとき、または入り直した人がその試合を押したとき）。
  次の PR「得点入力の担当」で「誰が入れているか」を扱うので、そこでまとめて直す
- **0 対 0 だけが届いた試合。** 電波が無い間に 1 点入れて 0 対 0 に戻し、0 対 0 だけが届くと、入口の側では始まっていない扱いのまま（0 対 0 では live にしない決まり）。アプリの中で移って戻ると LIVE の見た目だが、開き直すと「呼出待ち」に戻る。珍しい場面なので今回は画面の決まりを優先した
