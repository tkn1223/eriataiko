# 結果LIVE を本物の得点につなぐ

作った日: 2026-08-30

## なぜ作るか

得点を保存する入口（`POST /api/matches/[matchId]/scores`）はできたが、**まだ誰も呼んでいない。**
`/courts`（結果LIVE）は見本の固定値を出しているだけで、押した点は画面を閉じると消える。

## やること

`/courts` を本物のデータにつなぐ。**得点の取得・保存・更新まで。**

### 1. 読む

いまの大会のコート割り当てを、Server Component が 1 回で読む。
読み取りは `createSupabaseServerClient()`（`src/db/server.ts`）。
**`getSupabaseAdminClient()` は使わない**（AGENTS.md の破ってはいけない 2 番目）。

読むもの:

| 何を | どこから |
| --- | --- |
| コートに割り当てられた試合 | `matches`（`court_number` あり、`status` が `live` / `waiting`） |
| 部のラベル | `divisions.name` |
| 「予選 1回戦」 | `matchups.round_name` |
| チームの色 | `matchups.side_a_team_id` / `side_b_team_id` → `teams.team_number` |
| ペアの名前 | `match_players` → `participants` → `players.name` |
| いまの得点 | `game_scores` |
| 「◯/◯ 試合消化」 | `matches` の数（`status = 'done'` の数 / 全部の数）。`count: 'exact'` + `head: true` で**行は読まずに数だけ**取る |

`getSession()`（`src/server/session.ts`）も読む。使いみちは 2 つ:

- 自分の試合に「あなたの試合」の印を付ける
- **観戦者には ＋/− を出さない**（押しても 403 になるだけ）

### 2. 得点を押す

**ゲームの枠を `max_game_count` 個ならべる。「ゲーム終了」ボタンは消す。**
枠が並んでいれば「次のゲームへ」を押す必要が無い
（`docs/specs/2026-08-29-score-input-backend.md` の「フロントに渡すこと」どおり）。

押したときの流れ:

1. 画面の数字をすぐ動かす（体育館の電波が細いので、返事を待たせない）
2. 裏で `POST /api/matches/{matchId}/scores` に `{ gameNumber, sideAScore, sideBScore }` を送る
3. 失敗したら**日本語のエラーを画面に出し、`router.refresh()` で DB の本当の値に描き直す**

送るのは「いまの点数」。連打しても送り直しても余分に入らない。

**「押す前に覚えておいた値」には戻さない。** 連打で 2 回送ったうち、古いほうが後から失敗しても
新しいほうの成功を巻き戻してしまうため（例: 0→1 を送信中に 1→2 を送信、1 が失敗・2 が成功したとき、
覚えた値に戻すと画面が 1 になり DB の 2 と食い違う）。送っているのは「いまの点数」なので、
読み直せば必ず正しい値に落ち着く。

**送信中の試合・ゲームは、他から届いた値で上書きしない。** Realtime の読み直しや
`router.refresh()` が、自分の送信中に割り込んで画面を巻き戻すことがあるため。

### 3. 他の人の得点を映す

`getSupabaseBrowserClient()`（`src/db/client.ts`）で `game_scores` と `matches` の変化を購読する。
**表によって扱いを変える。**

- `game_scores` の変化 → **読み直さず、届いた値をそのまま画面に当てる。**
  Supabase の Realtime は変更後の行（`match_id` / `game_number` / `side_a_score` / `side_b_score`）を
  そのまま届けるので、読み直す必要が無い。
- `matches` の変化（`waiting` → `live` など） → `router.refresh()` で読み直す。
  1 行だけでは「試合の入れ替わり」までは表せないため。**0.5 秒ぶんをまとめて 1 回**にする。

読み直さない理由は通信量。1 点ごとに見ている全員がコート 8 面ぶんを読み直すと、

```
3,500 回（1 日の得点の回数）× 100 人 × 6〜15 KB ＝ 2〜5 GB
無料枠は 月 5 GB
```

と、1 日で無料枠を使い切る計算になる。`matches` の変化は 1 日 96 回程度（コートの数 × 試合数）
なので、こちらは読み直しても通信量への影響は小さい。

`matches` と `game_scores` は既に配信対象なので、DB 側の追加作業は無い。

**送信中は自分の値を優先する。** 自分が今まさに送っている試合・ゲームについては、
Realtime で届いた値も props で読み直した値も当てない（「2. 得点を押す」の失敗時と同じ理由）。

**つながらなくなったとき（電波が切れたとき）は、帯を出して人に画面の更新を促す。**
`TIMED_OUT` / `CLOSED` / `CHANNEL_ERROR` のどれかになったら
「つながっていません。画面を更新してください。」を出す。
**取りこぼしを自動で埋める複雑な復帰処理はしない。** 黙って古い数字を見せ続けるより、
つながっていないことを正直に伝えるほうがよく、作りも単純になる。

### 4. 「まだ保存されません」の帯を外す

`/courts` からは外す。`/matches`（進行表）はまだ保存できないので、そちらには残す。

## やらないこと

- **試合を終了する / 終了を取り消す。** 入口はできているが、今回はつながない
- **`/matches`（進行表）の得点入力。** 2 か所ある問題は残したまま
- **棄権・不戦勝、順位・勝敗の計算**（見出しの「◯/◯ 試合消化」は行を数えるだけなので、これには当たらない）
- **コートを 8 面に固定すること。** 試合が割り当てられたコートだけ出す
- **CSV 取り込み**
- **本番への公開**

## 決めたこと

| | 決定 | なぜ |
| --- | --- | --- |
| 読み方 | Server Component で 1 回読む | 初回表示が速い。体育館の電波が細いので往復を減らす |
| 他の人の得点（`game_scores`） | **読み直さず、届いた値をそのまま当てる** | 1 点ごとに見ている全員がコート 8 面ぶんを読み直すと、3,500 回（1 日の得点）× 100 人 × 6〜15KB ≈ 2〜5GB で、無料枠（月 5GB）を 1 日で使い切る計算になった。Supabase の Realtime は変更後の行をそのまま届けるので読み直す必要が無い |
| 試合の入れ替わり（`matches`） | `router.refresh()` で読み直す。0.5 秒ぶんをまとめて 1 回 | 1 行では「試合の入れ替わり」までは表せない。1 日 96 回程度なので通信量への影響は小さい |
| つながらなくなったとき | **帯を出して人に画面の更新を促す。取りこぼしを自動で埋める処理はしない** | 黙って古い数字を見せ続けるより、つながっていないと正直に伝えるほうがよく、作りも単純になる |
| 押したときの見た目 | **先に画面を動かし、裏で送る。** 失敗したら `router.refresh()` で読み直す（覚えておいた値には戻さない） | 返事を待たせると連打で数えそこねる。「押す前の値」に戻すと、連打中に別の送信が先に成功していてもその分まで巻き戻ってしまう |
| 送信中の値 | **他から届いた値（Realtime／読み直し）で上書きしない** | 自分がいま送っている試合・ゲームに割り込んで画面が巻き戻るのを防ぐ |
| ゲームの枠 | **`max_game_count` 個ならべ、「ゲーム終了」を消す** | 枠があれば「次のゲームへ」を押す必要が無い。0 対 0 は数えない決まりがあるので余った枠は害にならない |
| 観戦者 | **＋/− を出さない** | 押しても 403 になるだけ |
| コートの数 | **実データにあるコートだけ出す** | 何面使うかは大会ごとに変わる。設定を足すのは今回やらない |

## 残した宿題

- 試合を終了する / 終了を取り消すを画面につなぐ
- **「まだ行の無いゲームの枠を押しても保存される」の画面テストを足す。**
  手で押して確かめてはいる（第2ゲームの枠を押すと行ができて 1 対 0 が入り、ページの再取得も 0 件）。
  ただし自動では踏めていない。`supabase/seed.sql` のコートに割り当てた試合が 1 ゲーム制で、
  2 ゲーム目以降の枠が出ないため。3 ゲーム制の試合をコートに 1 つ置けば書ける
- `/matches`（進行表）の得点入力。結果LIVE と 2 か所ある問題を片付ける
- コートの面数を設定で持つ（いまは試合が入っているコートだけ出る）
- 棄権・不戦勝、順位・勝敗の計算
- CSV 取り込み
