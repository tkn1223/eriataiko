# 結果LIVE（/courts）— コートの状況と得点入力（保存はまだ）

作った日: 2026-08-19

## なぜ作るか

`/courts` は 4 画面のうち最後に残った「準備中！！」。トップ（`/`）を開くとここに飛ぶので、
大会当日に一番よく見られる画面になる。コート 8 面の「いま」を一覧し、
進行中のコートではその場で得点を押せるようにする（参考アプリのトップと同じ）。

保存する場所がまだ無いので、見本の固定データで作る。入れた点はその場限り。

## やること

`/courts` に次を出す。見た目は運用中のアプリ（badminton-app）のトップに合わせる。

**上部**

- 見出し「結果LIVE」
- 「予選リーグ」の黒い丸ラベル ＋「2/48 試合消化」（見本の固定値）
- 「入れた点はまだ保存されません（画面を閉じると消えます）」の帯（進行表と同じ見た目）
- 「コートの状況」のセクション見出し

**コートのカード（8 面、縦 1 列）**

- 進行中のコート: 枠線が強調色。「コート1」＋ 点滅つき「LIVE」
  - 部のラベル ＋「予選 1回戦・1ゲーム目」
  - チームごとに 1 行: チーム色ドット＋ペア名 ／「−」「＋」（46px 角）／大きな得点（36px・強調色・等幅）
  - 終わったゲームは「第1ゲーム 21-15」のチップ
  - 「ゲーム終了」（どちらかが 21 点に達したら強調色に変わる）
  - 破線区切りで「次」ラベル ＋ 部 ＋ 次の試合のペア名
- 空いているコート: 「呼出待ち」（次が決まっている）または「予定なし」＋ 次の試合
- 自分の試合中のコート: 枠が強調色で太くなり「あなたの試合」の印。次が自分なら名前を強調

## やらないこと

- DB の読み書き（`src/db/` を触らない。`src/app/api/**` も作らない）
- 得点の保存（その場限り。帯で明示）
- 「ゲーム終了」での結果確定・順位への反映（次のゲームに進むだけ）
- 21 点・デュースの勝敗判定
- 「自分が誰か」を覚える仕組み（見本データで決め打ち）
- 「呼出待ち」を自動で次の試合に切り替える仕組み

## 受け入れ基準

- [ ] 終わったゲームが「第1ゲーム 21-15」のチップで出る
- [ ] どちらかが 21 点に達すると「ゲーム終了」の色が変わる

- [ ] 各コートに「次」の試合（部・ペア名）が出る。次が無いコートには出ない

- [ ] 「まだ保存されません」の帯が出る
- [ ] 375px と 390px で、ページ全体が横にはみ出さない。ペア名が途中で切れない
- [ ] 押せるところ（−・＋・ゲーム終了）はどれも 44px 以上
- [ ] `/courts` の画面のコードが `src/db/` を import していない

## 決めたこと

- **得点の入力口は 2 か所のまま**（結果LIVE のカード直接 ＋－ と、進行表のシート）。
  参考アプリも両方にある。保存を作るときに同じ仕組みを 2 画面から呼ぶだけなので二重作りにはならない。
- **同じ部品が 3 か所目になるものは共通化する**（部のラベル・「あなたの試合」の印・
  「まだ保存されません」の帯は進行表と同じ見た目。3 画面目に達したものはまとめる）。

## 残した宿題

- 得点を保存する（表と書き込みの入口。次の本命）
- 観戦の人には ＋− を出さない仕組み（いまは誰でも押せる見た目。保存＝入場の仕組みとセットで）
- 21 点・デュースの判定、結果の確定
- 0-0 のまま「ゲーム終了」を押せてしまう（意味のない記録が残る）。21 点・デュースの判定と一緒に、保存を作るときに線を引く
- 「呼出待ち」→ 次の試合の自動繰り上げ
